# 萌萌日程（astrbot_plugin_mine_chat）

> 日程排布 × 主动消息。角色有自己的生活，主动才会显得自然。

让 Bot 拥有一份贴合人设与世界观的日常生活，并据此在合适的时机主动找用户说话。

## 它解决什么问题

纯随机间隔的主动消息容易变成机械骚扰（「在吗」「最近怎么样」）；纯日程设定又只是躺在配置里的背景板。
本插件把两者绑成一件事：**日程产生「可分享碎片」，主动消息消费它**。

所以角色的主动消息通常发生在「它刚做完一件具体的事」之后，而不是凭空想起你。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| **人格（persona）** | 状态作用域的主键。日程、节流、未回复计数全部挂在人格上 |
| **窗口（umo）** | 一个会话通道，如 `aiocqhttp:FriendMessage:10001` |
| **主窗口** | 该人格主动消息的**唯一**投递目标（v1 固定私聊） |
| **共享窗口** | 与主窗口同人格的其他窗口（主要是群聊），只共享日程、不接收主动消息 |
| **可分享碎片** | 日程条目里的 `message_seed`，例如「楼下便利店关东煮打折」——主动消息的燃料 |

同一人格的私聊与群聊共享同一份生活，因此角色在群里说过的「下午在开会」不会和私聊矛盾。

> **启用条件（显式配置驱动）**：插件只有在「已选人格 + 已绑定投递窗口」后才运行；
> 缺任一项都视为未启用——不生成日程、不注入、不主动发消息，所有钩子保持静默。
> 在控制台「人格与窗口」页完成这两步即可启用。

## 工作方式

### 1. 日程生成（每天一次）

- 触发：当天过了「每日生成时间」（默认 `07:30`）后的**首次使用**懒生成，带生成锁与日期幂等。
- 跨天延续：还没到今天的生成时间，则继续沿用昨天的日程，避免凌晨换日导致生活断裂。
- 上下文：人格提示词的**生活向段落**（身份/外貌/作息/性格/喜好/雷区/小习惯；对话规则与画图流程会被裁掉）
  + 世界观 + 角色补充设定 + 日期性质（工作日/周末/节日）+ 作息 + 最近几天活动（避重）
  + **当天的季节/天气、基调与一条小主线**（由 persona + 日期确定性随机，见下）
  + 前几天遗留的状态 + 好感度档位/情绪底色（可选）。
- 输出：严格 JSON，结构 `{schedule:[{time,end,activity,mood,message_seed,basis,confidence}]}`。
- 校验：代码侧强制时序单调、不重叠、覆盖整天、单条 10~600 分钟；不合格按「格式 / 时序 / 重复 / 质量」分级重试；
  仍不合格走规则兜底模板（标记 `fallback`，稍后可自动重试）。

### 2. 日程注入（每次回复前）

默认把动态块追加在用户消息之后（`extra_user_content_parts`，不破坏模型前缀缓存），形如：

```
【现在的时间】2026-09-30 周三 14:35
【你此刻】14:00-15:00 在公司开周会（心情：有点犯困）
【刚才】13:20 吃完午饭
【稍后】15:30 去楼下咖啡厅写点东西（约 55 分钟后）
【可以顺口提的】那家咖啡厅的拿铁太甜了
【你上一次主动发给对方的消息】（12:10 发的）「楼下的关东煮到货了，买了两串」（用户现在很可能就是在回它）
（这是你自己发出去的原话，不是对方说的。对方问的就是它，顺着答；绝不要说「我没发过」「我没说过」。）
以上是你自己的生活设定，不是用户的经历。用户不问就不要主动汇报细节；被问到再自然地说出来，不要像念行程表。
```

可切换注入位置为 `system_prompt`（部分不支持多模态内容块的模型用这个），也可整块关闭。

最后那一行「你上一次主动发的」是 v1.1.0 的重点：它决定「用户追问主动消息时，角色能不能对上话」。
字数不够时**优先保住这一行**，日程细节先让位；窗口由 `inject.echo_window_minutes`（默认 360 分钟）控制。

除此之外还有一层兜底：每轮 LLM 请求前都会检查「最近一条主动消息是否已在本轮上下文里」，
缺了就补进 `req.contexts`（由 AstrBot 自己落库）。这样即使写库被 AstrBot 的整表覆盖抹掉、
或者被对话压缩删掉，角色也不会「忘记自己说过什么」。

### 3. 主动消息

- 调度：60s 心跳（可调，下限 30s）+ 事件唤醒（用户说话后立刻重算）。
- 时机：`next_at` = 下一个日程片段起点 + 0~20 分钟随机抖动，并自动避开免打扰时段。
- **有序闸门链**（不满足即拒绝，原因码落库）：

  | # | 闸门 | 默认 |
  | --- | --- | --- |
  | 1 | 总开关 / 人格开关 | 开 |
  | 2 | 免打扰时段 | `23:00-08:30`（支持跨天） |
  | 3 | 角色睡眠片段 | 不发 |
  | 4 | 每日上限 | 6 次 |
  | 5 | 两次最小间隔 | 45 分钟 |
  | 6 | 连续未回复上限 | 4 次 |
  | 7 | 用户刚说过话 | 10 分钟内不发 |
  | 8 | 发送互斥 | 单人格串行 |
  | 9 | 到点 | `now >= next_at` |
  | 10 | 候选有效 | 当前/最近片段存在 |

- 生成：LLM 一次，输入为当前片段 + 碎片 + 最近对话 + 上次主动内容 + 未回复次数；输出可用 `---` 拆成最多 3 条短消息连发。
- 配图：开启「主动消息可以配图」后，每次主动按概率（默认 25%，每日上限 2 张）从图库目录
  随机挑一张随消息附上。图来自本地目录（默认 `data/plugin_data/astrbot_plugin_mine_chat/images`，
  可自定义）——用 comfyui-anima / nai 等把图生成好放进去即可，本插件不在线生图。
  文件名（去扩展名）会作为画面线索告诉模型，但提示词同时要求它**不要在文字里描述图片**，
  效果就像真人随手发图。
- 投递：`context.send_message(umo, MessageChain)`；返回 `False`（未找到平台）视为未送达，不写历史、不计数。
- 写回：成功后写入对话历史，并在下一轮注入「你刚才主动发了 X」，防止上下文裁剪后角色失忆。
- 插嘴检测：生成期间用户说话了 → 本次作废。

## 指令（仅管理员）

| 指令 | 说明 |
| --- | --- |
| `/日程` | 查看当前角色今天的日程（标出「此刻」） |
| `/日程 刷新` | 强制重新生成今天的日程 |
| `/主动` | 查看主动状态：投递窗口、下次候选、今日已发、未回复、免打扰 |
| `/主动 on` / `/主动 off` | 运行时开关（不写配置，重启后按配置） |
| `/主动 now` | 立即触发一次（仍受静默/睡眠/上限约束） |

## 控制台

AstrBot 插件页 **萌萌日程**（`pages/schedule-console/`）：

- **总览**：此刻的生活、主动状态、最近裁决，可一键「立即主动」。
- **日程**：时间轴查看当天安排，点条目可直接改写活动 / 心情 / 可分享碎片，支持重新生成。
- **主动消息**：运行状态、开关、立即一次，以及裁决日志（时间 / 结果 / 原因 / 内容）。
- **人格与窗口**：人格档案启停、查看自动登记的窗口绑定、手工增删绑定与设置主窗口。
- **配置**：按分区编辑全部配置项。

## 配图与表情包（主动消息可附图）

| 通道 | 来源 | 说明 |
| --- | --- | --- |
| 配图 | 本地图库 / ComfyUI萌绘（anima）/ 直连 | 开关 + 概率 + 每日上限；画风（动漫/真人）与提示词可配 |
| 表情包 | **调用萌萌表情包插件**（moe_meme v0.2.0+ 跨插件 API） | 独立概率 + 独立每日上限；token/缓存/去重由 moe_meme 管理，本插件零配置。未安装或版本过旧时回退直连站方（此时才需填「表情包 API Token（直连兜底用）」） |

两条通道独立掷骰；同一条消息两者都命中时配图优先、表情让位。每次决策（命中/未中/超限/失败/让位）都进裁决日志，控制台「主动消息」页可查。

**出图怎么锁定角色与画风**（ComfyUI萌绘方式）：插件会把人格设定里的角色身份、
控制台「世界观与角色」页填写的**角色锚点**（外貌描写，建议带上 `1girl` / `1boy`），
以及所选**绘图画风**的标识，一起**强制写进最终出图提示词**（不是只交给模型自觉），
并在负向提示词里自动补上相反画风的排除词。锚点留空时依次尝试知识库「角色形象」与
人格设定，此时只能锁住角色名、锁不住发色瞳色——想稳定画出本人，请把外貌写进锚点。
裁决日志 `img_ok` 的内容列记有实际喂给萌绘的提示词，可据此核对。所有出图（含
生成失败回退）都以 `raw_prompt=True` 交给萌绘，避免它用 LLM 把提示词二次改写成
「写实中文」而洗掉角色与画风标识；若仍偶发跑偏，请对照萌绘图库里的最终正向提示词，
并核对目标工作流是否设了 `require_prompt=false`（会用固定提示词整体替换传入的 prompt）。

命中却拿不到图时（萌绘出图失败 / 图库为空 / 表情拉取失败），默认**整条取消**：连文字一起不发——
「说要发图却没有图」比什么都不说更出戏。若更看重「别白等一次主动机会」，可打开配置项
**「配图/表情获取失败时仍发文字」**（`proactive.media_fallback_text`）：此时降级为纯文字发出，
本条不带图，并在裁决日志里记一条 `img_fallback` / `sticker_fallback`。

## 跨插件联动（都可选，缺了自动降级）

| 插件 | 用在哪 | 拿不到时 |
| --- | --- | --- |
| **萌萌好感度** `astrbot_plugin_moe_affinity`（契约 `affinity.v1`） | ① 关系档位（陌生/眼熟/熟悉/亲近/亲密/羁绊）→ 日程里有没有「为对方留一份」的细节、主动消息这次该有多主动；② 情绪四轴 → 当天的情绪底色与文案语气 | 不加任何相关段落，完全按人格自己判断 |
| **CosyVoice3** `astrbot_plugin_cosyvoice` | 主动消息偶尔真的「开口说一句」：概率 / 每日上限 / 音色 / `append` 或 `replace` 可配 | 只发文字；合成失败自动补发文字 |

三条边界：

1. 好感度**只读**。写事件默认关闭（`proactive.affinity_event`）——好感度应当由用户真实互动产生，
   主动消息自己不该加分；开启时用 `source="mine_chat"`，不占对方的每日增减额度。
2. 日程铁律 1 不破：所谓「为对方留的痕迹」只作为生活细节出现（多备一份食材、把东西放在顺手的位置），
   **不写对话、不写「等」、不占条目**；关系不够时这一段根本不会进提示词。
3. 语音与配图、表情**互斥**：一条消息只承载一种媒体，图和表情优先，语音让位时不消耗当日计数。
   朗读文本会先清洗（括号里的动作神态、颜文字、`---`、markdown 一律不念），
   纯符号内容视为无内容直接跳过。

## 每天不一样 + 逻辑自洽（v1.2.0）

同一份提示词每天只换日期、再附一句「请避免重复」，模型只会换措辞不换内容；
而模型不知道「今天什么季节、什么天气、昨天留下了什么」，就只能每次在真空里编——
**无聊和自相矛盾是同一个病根**。

每天生成前先由 `life.py` 定下当天的客观事实（全部确定性随机，seed = persona + 日期，
同一天多次重试不漂移）：

| 事实 | 作用 |
| --- | --- |
| **季节**（深秋/隆冬…，带体感） | 禁反季物象：冬天的冰镇西瓜、凉席、蝉鸣；夏天的羽绒服、暖气、积雪 |
| **天气**（小雪/阴雨/晴/阴/大风，按气候带加权） | 禁天气冲突：下雪晒被子、晴天打伞写雨声；同一天不能一半晴一半雨 |
| **基调**（平常/慢半拍/有点忙乱/出门走动/几乎不出门） | 「几乎不出门」不许出现去超市；「出门走动」必须有外出 |
| **一条小主线**（42 条，分 6 类） | 要求 2~4 条里推进（铺垫→在做→收尾）；**最近三天用过的类别不再发**，避免隔天循环 |
| **必须覆盖的生活面**（1~2 项） | 从现在/休闲/身体/外出里挑，避免一整天只剩工作和吃饭 |
| **最近几天遗留的状态** | 昨天自报「感冒还没好」，今天要么延续、要么明确交代好了 |

模型的输出因此多了一个可选字段 `state_after`：只写「到今天结束还没结束」的东西
（感冒没好、菜还剩半颗、借的书没还、灯坏了没修）。它随日程存进 `daily_plan.meta_json`，
第二天以【这几天延续下来的状态】喂回去。**不做推断**——模型没写就是没有。

另外还设了三条硬性「不完美」要求：至少一条没做成/被打断/半途而废，至少一条纯为舒服的闲事，
至少一条与外面世界有关。铁律里明确写着「不要写成效率清单」。

条目数默认 **10~18**（6 条一天 = 每条约 4 小时，必然只剩四五个场景，读起来一定干）。

### 矛盾扫描的保守策略

`life.scan()` 只报能明确判定的矛盾，而且**因矛盾触发的重试最多一次**：第二次仍有问题就接受
这份日程，只扣 8 分并记一条日志（`日程仍有轻微逻辑问题，已接受`）。宁可留一条轻微矛盾，
也不要把一整天的日程换成通用兜底模板——那比矛盾难看得多。

## 数据

- 位置：`data/plugin_data/astrbot_plugin_mine_chat/mine_chat.db`（SQLite，WAL）。
- 表：`persona_state` / `window_binding` / `persona_kb` / `daily_plan` / `plan_item` / `proactive_state` / `proactive_log` / `meta`。
- 所有状态按 `persona_id` 归档；换插件版本不会丢（不放在插件安装目录）。

## 安装

1. 从 `dist/astrbot_plugin_mine_chat_v<版本>.zip` 安装（或克隆仓库到 `data/plugins/`）。
2. 打开控制台「**人格与窗口**」页：**选择人格并「设为当前人格」**，再**绑定一个私聊窗口**
   （格式 `platform:FriendMessage:QQ号`，如 `aiocqhttp:FriendMessage:10001`）并勾选「设为主窗口」。
   两项都完成后插件才启用——此前它保持静默。
3. 在配置里填 **世界观 / 角色补充设定**（写得越具体，日程越贴人）。
4. `/日程` 确认日程，`/主动` 确认状态。

## 开发

```powershell
# 语法自检
uv run --no-project --python 3.12 python -m compileall -q *.py

# 纯函数自检（不依赖 astrbot 运行时）
uv run --no-project --python 3.12 python tests/test_core_logic.py

# 构建控制台（必须用脚本：它会把 metadata.yaml 的版本号注入 version.ts）
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_webui.ps1

# 打包（先升 metadata.yaml 的 version 并在 CHANGELOG 顶部加条目）
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_zip.ps1
```

约定：

- 包内模块一律相对导入（`from . import xxx`）。
- **新增顶层 `.py` 模块**必须同时更新两处：`main.py` 的 `_RELOAD_MODULES`（热重载列表）
  与 `build_zip.ps1` 的 `$includeList`（后者有守卫会直接报错，前者漏了会静默不生效）。
- **新增配置键**直接在 `_conf_schema.json` 对应分组的 `items` 里加（嵌套 object 结构）：
  AstrBot 内置配置页与控制台配置页都由它驱动，不需要改前端；控制台保存走点路径
  （如 `persona.active`）。
- 界面文案只写简体中文，**不引入 i18n**。

## 已知边界（v1）

- 群聊只共享日程、不主动发言；多用户 / 多人格并发未做验证。
- 语音与 TTS 不支持。
- 不做用户作息学习、天气、位置、细化剧本与观察对账（这些是参考项目的重武器，本插件刻意做减法）。
- `schedule_forbidden` 只处理公历固定节日，不含农历节日（春节、端午、中秋等）。
